# 06 — Security audit

Status **in progress**, 2026-11-08. This is local code/test evidence and risk triage, not a penetration test or assertion of live exposure. Hosted services, production policies, keys, user records and deployments were not accessed. Do not place secrets or real customer data in tickets, reports, logs or browser builds.

| Risk | Evidence / current local posture | Status and required verification |
|---|---|---|
| Draft and project privacy | Earlier local PGlite reproduced anonymous draft/project disclosure. Local 00015/00020 restrict direct reads and project published projections; P0 32/32 and snapshot 21/21 passed. | **Testing locally / hosted blocked.** Review all real RLS, grants, extra permissive policies, cached snapshots, public RPCs and editor privileges with independent sessions. A published document exposes all projected props/theme, including visually hidden content. |
| Public order abuse and replay | Earlier anonymous direct RPC created an order and decremented synthetic stock. Local 00015 revokes public direct RPC; Edge receipt narrows PII. | **Testing locally / hosted blocked.** Replay is not payload-bound/authenticated, known references may expose limited details. Test direct API denial, independent transactions, receipt privacy and failure/rollback. |
| Browser demo/admin identities | Demo gate is browser-local; `src/config/env.ts` may expose `VITE_BAGISTO_ADMIN_TOKEN` in a client bundle. Local Supabase mode verifies Auth identity before mounting protected UI. | **In progress.** A valid Auth identity is not staff authorization; test actual capabilities/RLS. Never ship admin/service credentials to browsers; audit history and rotate if real secrets are found through an approved process. |
| Intake abuse | Local 64 KiB JSON limits, exact Turnstile action checks and optional strict mode exist. Legacy/unset behavior still fails open for missing secret and some limiter failures. | **Testing / hosted blocked.** Owner must approve mode, trusted proxy and WAF/global budgets; test actual Edge/Turnstile/rate limits and rollout, not synthetic tokens alone. |
| Procurement/settings | Local 00018/00019 narrow some reads/projections. | **Testing / hosted blocked.** Owner approves exposure; test actual effective policies (permissive policies combine with OR), writes, RPC execution and service-role/default grants. |
| AI | Local authenticated `crm.manage` check and attempt quotas exist; grounding is not independently trusted and quotas are not monetary budgets. | **Blocked.** Keep hosted AI disabled until privacy, trusted retrieval, adversarial tests, provider-side spend controls and incident shutdown are approved and verified. |
| CMS content | Custom rich-text sanitizer and builder styles/links need security review; new 13-block preflight is narrow and does not sanitize arbitrary public props. | **In progress.** Keep experimental route off in production and protect staging at host level. Test XSS, links, styles, image/media, hidden data and server-side noindex. |
| Production/QC separation | Owner decision 2026-11-08: the last stage editor cannot record the pass. Local candidate 00022 refuses it with `42501` before any write (no inspection row, no revision bump) and the demo store mirrors the rule; a failure from the same actor is allowed. 60/60 PGlite, 25/25 browser. Still missing: a dedicated QC role (both seats hold `page.manage`), audit retention/tamper evidence, hosted verification, and the single-staff operational cost. |
| Storage/uploads | Local project bucket migration and media code exist. | **Blocked.** Verify actual bucket policies, MIME/size enforcement, signed URLs, cross-user isolation, deletion and orphan handling using synthetic files. |
| Data continuity and backups | Customer/lead linking is partially multi-step; actual backup/restore and concurrent transactions untested. | **Blocked.** Obtain isolated staging, restore test, transactional identity/conversion tests and data-safe rollback plan; never overwrite real records for testing. |
| Public surface (grants vs enforcement) | `rehearsal/public-surface-matrix.mjs` applies all 27 migrations to isolated PGlite and separates *grants* from *enforcement*: the base schema grants SELECT on every public table to `anon`/`authenticated`, so a grant is not exposure — the deciding layers are RLS policies and the internal guard of each SECURITY DEFINER function. Local result: 61 tables, 124 policies, 48 functions; 17 content tables are anon-readable through a policy; `anon` holds exactly one write grant (`track_events`, analytics insert); the three tables with RLS and no policy are service-role only; every anon-executable definer function either carries a `has_cap`/`require_cap`/`auth.uid()` guard or is a documented public projection. 7/7, now a CI gate. | **Testing locally / hosted blocked.** This is repository state, not a hosted grant dump. Re-run the same matrix against staging with real roles; a permissive policy combining with OR across roles can still widen access. |
| Secrets and integrations | `.env` is tracked and `VITE_` configuration is browser-visible; actual values and historical validity have not been investigated here. | **In progress.** Review tracked history privately without echoing values; if a real credential is found, follow owner-approved rotation. Verify provider webhooks/auth and sandbox before activation. |
