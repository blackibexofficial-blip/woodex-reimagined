## Decisions recorded this review (do not re-litigate)

- **No POS.** The 2026-11-07 skip stands — the Ecommerce screen in Agency OS is a catalog/orders control center, not a register; the register is still out of scope.
- **No new migration for invoices.** 0001 already ships `invoices`/`payments` + `quote_invoice_snapshot` (idempotent, cap quote.manage) + `invoice_apply_payment` (cap finance.manage, auto status flip) and the payments policies are **finance-only reads**. The invoice surface here is adapter+UI; nothing was created hosted-side.
- **The 0001 snapshot RPC IS lossy** (invoice lands with subtotal=total=quote.total; discount/shipping breakdown not carried). Deliberate this round: fix requires a CREATE OR REPLACE of the RPC (would be migration 0012) — owner hasn't signed that off; labeled in code comments as "Phase-2 candidate".
- **Merge review is RPC-tombstone, never delete, and never automatic.** Candidates are derived (group non-merged `clients` by `email_norm`/`phone_norm`); merges go through `client_merge` (crm.manage); retired rows carry `merged_into` and remain in the audit view. Demo seeds one email-collision pair, one phone-collision pair and one pre-retired record. Score is always derived (orders · value · account-type), never stored — hosted `source` attribution lands only once hosted `clients` rows exist (merge backfill) — disclosed, not faked.
- **Control-center card adds zero RPCs.** `admin_overview` already emits `pending_invoices`/`open_quotes`/`pipeline_value`/`overdue_returns`/`published_pages` — the card passes it through. Demo store computes the same signals seeded (QOT-1001 sent → open). Bagisto baseline: zeros + comment (never invented). **Fixed in-repo as migration 0012 (2026-11-08):** identical function, only the two open-quote predicates change to lowercase (`'draft','review','approval','sent','revised'`) — now casing-consistent with the app write path; rehearsed 62/62. Hosted apply remains owner-gated; hosts must run 0001→0012 in order.
- **Tasks ride plain RLS, not RPCs.** 0001 `tasks_read`/`insert`/`update` = `has_cap('crm.manage')` (sales holds it); **no `tasks_delete` policy exists** — worked, never deleted, matching ledger posture. Free-text client labels are deliberately demo-only: hosted mode has `client_id` (FK) and no label column, so the Supabase adapter surfaces related refs (quote/order/lead/site-visit) instead of inventing one; code comments say so. Demo seeds: TSK-1001 (Clifton Villa 9, overdue, normal), TSK-1002 (Gulberg Residency, due today, high).
- **Leads kanban needs no new schema or RPC:** HTML5 drag-and-drop (no library), five **lowercase** stage columns matched to the stored `lead.status` values; optimistic move with rollback on failure. Board ignores pagination/status-filter (fetches ≤100 rows). Site visits ride 0001 `site_visits` as plain RLS (`read/insert/update`, crm.manage) — the oft-cited `site_visit_schedule` RPC **does not exist** and was not invented; `reminder_task_id` stays unlinked pending an owner-approved migration. Creating a visit resolves the NOT-NULL `client_id`: explicit ref → `client_links` lookup → auto-create an identity client from the lead (`source: 'lead'`, kind by company presence) + link insert — hosted `clients_insert`/`client_links` policies re-checked (crm.manage), nothing applied live. Demo seeds SV-1001 (Completed measure-up, Bilal Ahmed) + SV-1002 (Scheduled +3d warehouse, Kashif Mirza). Also fixed a pre-existing demo off-by-one: Kashif Mirza's identity was attached to `lead-1008` (Fatima Raza's lead) in the quote seed, in `client_links`, and here — now uniformly `lead-1007`. Score: 68/68 rehearsal (+3 site-visits asserts).
- **Attribution is first-party only.** The campaign view reads UTM tags/consent captured on the storefront lead form — **no pixel is deployed, no third-party tracker is wired** (pixel go-live is an owner decision: provider, consent copy, CMP). Spend / CPA / ROAS are deliberately absent — storing ad spend is an owner decision; derived pipeline/won/win-rate per campaign are estimates, never faked. Demo attribution seeds enriched (Omar → linkedin/organic `hq-fit-out-q4`; Fatima → instagram/organic `minimal-home-look`; Mahnoor → youtube/organic `study-room-makeover`; Owais → facebook/cpc `reception-counter-boost`; Mariam → google/cpc `6-city-rollout`). e2e 54/54 (+2 campaign + +6 UI asserts).
- **Projects practice workspace is payload-only.** BOQ/milestones/files serialize into `projects.payload` (no migration; hosted-compatible by construction — `payload jsonb` absorbs arbitrary keys). BOQ = **planned cost only**. Milestones = Done 1 / In-progress 0.5 / Blocked & Not-started 0 roll-up; **production/dispatch tab explicitly out of v1**. Files = metadata-only, uploads simulated in demo (real Supabase Storage = owner-gated hosted step; RLS unscoped for it); no bytes persist or leave the sandbox. Seeds: Grooming Lounge (id 7, full: 11 BOQ rows / 8 milestones / 4 files) + DHA Corporate Tower (id 1, all-done close-out job).
- **Invoice numbering:** legacy INV-26-#### with year prefix dropped — uses identity (INV-1001+) matching REF discipline elsewhere.
- **No deletes on ledger documents.** Legacy's red-bin delete is not ported.
- **Demo mode:** invoices seeded (Issued + Partially paid + one logged payment) so the page is fully previewable offline.
